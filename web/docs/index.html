// openframeworks → webassembly → github pages

Write C++. Push. It's live in a browser.

No local toolchain, no manual build. A GitHub Actions workflow compiles your openFrameworks sketch to WebAssembly and publishes it at a public URL.

⚡ Publish a sketch 🖼️ Gallery ▶ Live demo ★ Source

#Overview

Building an openFrameworks app for the web normally means installing Emscripten, downloading openFrameworks, compiling the whole framework, then compiling your sketch — all locally. This project hands all of that to a GitHub Actions workflow that runs on GitHub's servers.

The only files you maintain are your source in src/ (and optional assets in bin/data/). The workflow supplies everything else — and caches the compiled framework, so after the first run, builds drop from ~10–15 min to a couple of minutes.

#One-click uploader

The fastest route skips the template entirely. The web uploader is a browser app that wires up GitHub for you.

🔑 Paste a GitHub token → drop in your src/ → “Create my project”
↓

🖥️ The uploader — runs entirely in your browser

① Create a new repository
② Commit src/ (and bin/data/)
③ Add the current web.yml workflow
④ Turn on GitHub Pages
↓
🌐 GitHub Actions builds it → your sketch is live
No server, no setup. The token you paste stays only in your browser tab and is sent straight to GitHub — never to us. See the Privacy Policy.

#Quick start

Option A — Web uploader (easiest)

Open the uploader, paste a token, drop in a .zip of your project (with src/ and bin/data/ inside), and click Create my project.

Option B — Use the template

On the repo, click Use this template, replace the demo code in src/ with your own, push to main, and do the one-time Pages setup.

Option C — Add the workflow to an existing repo

Copy .github/workflows/web.yml into your repo, make sure your code is in a top-level src/ folder (assets in bin/data/), push to main, and enable Pages.

Standard layout required. The workflow looks for exactly src/ and bin/data/. Don't commit your own bin/, obj/, Makefiles, or an openFrameworks copy.

#Enable GitHub Pages (one-time)

The workflow builds on every push, but GitHub won't publish until you point Pages at Actions:

  1. Repo → Settings → Pages.
  2. Under Build and deployment → Source, choose GitHub Actions.
  3. Push again (or re-run the workflow) and it deploys.
https://<your-github-username>.github.io/<your-repo-name>/
First visit may reload once. A tiny service worker installs the cross-origin-isolation headers openFrameworks' threads need, then reloads. Normal — once only.

#Writing code that works on the web

  • Target openFrameworks 0.12.1 — the version the workflow downloads.
  • Window setup. src/main.cpp uses ofGLWindowSettings in OF_WINDOW mode — correct for the web.
  • Fullscreen must be user-triggered (a key or click), routed through Emscripten — you can't force it at startup. The demo wires the f key and a Fullscreen button.
  • Assets load relative to bin/data/ — e.g. img.load("photo.png").
  • Don't block the main thread. No infinite loops — the browser needs each frame to breathe.
  • Handle resize. The canvas can change size; re-allocate FBOs in windowResized().

#What the workflow does

.github/workflows/web.yml in plain English:

  1. Trigger on every push to main (and manually from the Actions tab).
  2. Check out your repo into sketch/.
  3. Clone openFrameworks 0.12.1 and download its prebuilt web libraries.
  4. Start Emscripten (emscripten/emsdk:4.0.4) in Docker.
  5. Build openFrameworks for the web — the slow step, but cached between runs with actions/cache, so repeat builds skip it.
  6. Set up your project — copy src/ + bin/data/ into an oF app, add the web Makefile, a bin/data placeholder, and a reallocarray shim.
  7. Compile your sketch → .wasm + .js + .html.
  8. Make it Pages-ready — add the service worker for cross-origin isolation (and, in this repo, a combined offline/PWA worker), reskin the page, and fix fullscreen.
  9. Package & deploy to GitHub Pages.

#Troubleshooting

Open the Actions tab, click the failing run, and read the logs — the error is almost always in the Build the sketch for the web step.

SymptomLikely cause & fix
C++ compile errorsA bug in your src/ or an API missing in oF 0.12.1. Fix what the compiler points at.
Builds locally, fails hereYou're on a different oF version locally. Match 0.12.1, or pin the workflow.
Blank / stuck on “Downloading…”Open the browser console (F12). Often a missing asset path or a crash in setup().
Assets don't loadThey must be in bin/data/, loaded with relative paths, committed, with exact name/case.
Fullscreen does nothingIt must be triggered by a key/click, not called automatically.
Deploy step failsPages isn't enabled or isn't set to “GitHub Actions.” Do the one-time setup.
Reloads once on first visitExpected — the service worker installs the threading headers, then reloads.

#FAQ

Do I need to install anything?

No. You can edit on GitHub directly. For local dev, install openFrameworks 0.12.1 and use your IDE — but the web build only happens on GitHub's servers.

Why does the page reload once?

openFrameworks web builds use threads, which need special security headers GitHub Pages can't send. A tiny helper installs them and reloads so they take effect. First load only.

Is the uploader's GitHub token safe to paste?

It lives only in that browser tab (sessionStorage) and goes straight to GitHub's API — never to any server of ours. Use a short expiration and the minimum scopes, and revoke it anytime in GitHub settings.

How long until my changes are live?

The first build is ~10–15 min; cached builds are a couple of minutes, plus a short propagation delay after deploy. Watch the Actions tab.

Is my sketch public?

If your repo is public and Pages is on, anyone with the URL can view it. Private-repo Pages needs a paid GitHub plan.
